Barncept · Reasoning

Your understanding outlives your code.

Code is rewritten, frameworks come and go, folders get reshuffled. What lasts is how you understand the domain. With Barncept you design a reusable Template, then create Constructions that follow it. Describe what each building block means, arrange leaves, lists and maps, and add real members to each Construction. Every saved change has a history, and each Construction keeps the exact Template revision it started from.

Meaning first

Types that explain themselves.

A Template names the types of thing in one subject. Each building block has an identifier, a name and a meaning written in plain words. A type is a leaf, which holds nothing, a list of one type, or a map of several. A house is a map of a ground floor, an upstairs and a garden; its bedrooms are a list, and each bedroom is a leaf.

Months later, anyone can open the tree and understand not just what exists, but what each thing is for. Each Template’s Glossary puts every type and its meaning on one page, so a newcomer, or an AI agent, can learn the vocabulary in one read.

Always valid

A change that would break it is refused.

Create a Construction from a saved Template. Its required map children are made for you, and its lists start empty. Use + Add to give a list real members, each with its own name. Keeping the tree in line with its types is Barncept’s core job. It is never left half-broken: a type nobody has described, a map that holds itself forever, two members of one list with the same name, or a member added where there is no list is refused, with a message that says why. That makes it safer to drive than the file underneath, whether a person, a program or an AI agent is doing the driving.

A file that was broken outside Barncept fails loudly when it is read, and says what is wrong and where.

Before any change is kept

  • Add a Back bedroom to Bedroomskept
  • Add a second Back bedroomrefused: the name is taken
  • Add a Pantry to the Kitchenrefused: a leaf holds nothing
A shared capability

One engine. Clear boundaries.

Barncept keeps concepts through a generic interface, and knows nothing of what they are about. Barnark uses it for architecture templates. Barnspec uses its generic document store to keep each area of business. Each tool keeps its own API and domain rules, so Barncept does not need to know what either tool means by what it keeps.

Reusable rules

Design once. Construct separately.

A Template’s tree shows its fixed children and the structure each list repeats. The sidebar groups its reusable Maps, Lists and Leaves. Select a building block to see its meaning and uses, then choose Edit. Drag a building block’s grip onto a compatible target, or use the keyboard controls to add or replace a connection.

Save and Cancel belong to the object being edited. Save records the whole session as one revision; Cancel restores the saved version. Shared changes and losses ask for confirmation, and leaving an unfinished edit offers Save, Discard or Stay.

Real members

One Template. Independent Constructions.

Choose Construct, give it a name, and Barncept opens the new Construction’s tree. Add, rename or remove list members within an explicit Save/Cancel session. Required map children and the captured building-block rules stay protected.

Willow Cottage can have a Front bedroom and a Back bedroom while another house has different rooms. Each Construction keeps its exact saved source revision: later Template changes leave it intact. Overview links back to that source, even if the live Template is later renamed or deleted.

A record of change

History belongs to each object.

Templates and Constructions each have their own History, newest revision first. See when a change was recorded and what changed, expand a combined save, or open a revision’s read-only snapshot.

Construction creation records its first revision immediately. Later saves add revisions only when something changed. Historical snapshots and captured sources remain read-only; restoring or upgrading them is outside the current editor.

Realise it any way

One model. Any shape.

Barncept never decides what a tree becomes. A folder structure, a diagram and a set of documents are each one possible realisation, never the model itself. Turn the same tree into real folders, an architecture to check code against, or whatever you need next.

Four Template projections come built in. Open View and export under a Template’s Overview to preview or download its saved item tree, or export it from the command line. Construction exports are not available yet.

Barnark architecture templates use Barncept concepts too. Barnark manages its own templates and folder rules; the new Construction workflow is not integrated with Barnark yet.

  • Documentfor people: a heading per item, its meaning beneath
  • Foldersfor developers and tools, a README in each
  • Diagramfor a README, a pull request or a slide
  • Treefor a quick look

How it works underneath.

Everything above, in more detail, for when you want it.

Types and itemsLeaves, lists and maps, and the tree that follows them
  • Leaf: a type of nothing, such as Kitchen.
  • List: a type of exactly one type, such as Bedrooms, a list of Bedroom. Its items are its members, any number of them, each with a name you give it.
  • Map: a type of a set of types, each at most once, such as House, a map of Ground floor, Upstairs and Garden.

A Template names its root type, and types refer to each other only by name, so one type can be used in many places. Every item follows one type and has an id that Barncept generates. Skeleton is a read-only preview of the starting tree: the root and every required map child, down to empty lists and leaves. A new Construction starts there. Add two bedrooms to a House Construction and its tree reads:

House
|
+--Ground floor
   |
   +--Hallway
   +--Kitchen
   +--Living room
+--Upstairs
   |
   +--Bathroom
   +--Bedrooms
      |
      +--Front bedroom
      +--Back bedroom
+--Garden
   |
   +--Shed
   +--Beds

The editor marks a map, a list and a leaf each with its own icon, and its Help page explains every word it uses.

Templates, Constructions and History from the command lineThe same saved data as the browser

Read Templates and their building blocks, create Constructions, manage real list members and inspect revision history without a running GUI. Template and building-block editing remains in the browser.

$ vendor/bin/barncept template:list
$ vendor/bin/barncept template:show House --view=skeleton
$ vendor/bin/barncept type:show House Bedroom
$ vendor/bin/barncept construction:create House --name="Willow Cottage"
$ vendor/bin/barncept construction:list
$ vendor/bin/barncept construction:show CONSTRUCTION_ID
$ vendor/bin/barncept member:add CONSTRUCTION_ID --list=LIST_ITEM_ID --name="Front bedroom"
$ vendor/bin/barncept construction:history CONSTRUCTION_ID
$ vendor/bin/barncept construction:show CONSTRUCTION_ID --view=source

Replace the uppercase placeholders with the IDs printed by the list and show commands. Read commands support --json; member changes appear in the GUI and share its history. Member removal asks for confirmation.

Keeping many concepts in orderA check for CI

barncept check reads every concept and prints one line each: valid, or broken with what broke it. It fails on a broken concept or an unreadable file, so it fits in CI.

$ vendor/bin/barncept check
Barn: /path/to/project
Checking the concepts in /path/to/project/.barn/barncept/concepts
Garden: valid
Pond: broken: Type 'Pond' is of 'Fish', which is not one of the concept's types.
Exporting a conceptA document, folders or a diagram

Pick one realisation of a concept and export it. Nothing is ever overwritten: a file goes to a path that does not exist yet, and folders to an empty one.

$ vendor/bin/barncept export House --as=markdown --to=docs/house.md
$ vendor/bin/barncept export House --as=folder --to=house
$ vendor/bin/barncept export House --as=mermaid

Realising a concept as a PHP codebaseScaffold it, then check it still matches

Barnscaff, Barncept’s companion, turns a concept’s tree into a PHP codebase’s folders and files, and scans an existing folder to check it still matches.

$ vendor/bin/barnscaff scaffold House ./generated --apply
$ vendor/bin/barnscaff scan House ./generated
Conformant.
From PHPRead a concept, add a member, save it, export it

This example reads a House concept already saved in .barn/barncept/concepts/. Place the script in the project root, with Barncept and its command line or browser app installed.

<?php

use Rmb32\Barncept\Api\Factory\ConceptEditorFactory;
use Rmb32\Barncept\Api\Factory\ConceptStoreFactory;
use Rmb32\Barncept\Api\Factory\ProjectionWriterFactory;
use Rmb32\Barncept\Api\Factory\ProjectorRegistryFactory;
use Rmb32\Barncept\Api\ValueObject\ItemName;
use Rmb32\Barncept\Api\ValueObject\ItemPath;
use Rmb32\Barncept\Api\ValueObject\Projection\ProjectionKind;
use Rmb32\BarnPaths\Api\ValueObject\BarnPaths;

require __DIR__ . '/vendor/autoload.php';

$barn = BarnPaths::at(__DIR__);
$store = new ConceptStoreFactory()->create($barn->barnceptConcepts);
$house = new ConceptEditorFactory()->create()->addMember(
    $store->read('House'),
    new ItemPath('Upstairs', 'Bedrooms'),
    new ItemName('Front bedroom'),
);
$store->write($house);

$document = new ProjectorRegistryFactory()->create()
    ->get(ProjectionKind::new('markdown'))
    ->project($house);

new ProjectionWriterFactory()->create()->write($document, __DIR__ . '/house.md');
Get started

Design a Template. Make it real.

Barncept needs PHP 8.5, Composer and the ds extension. If the project has no barn, run init once to create .barn/, then open the editor. Existing Template files stay in .barn/barncept/concepts/ and appear in the catalogue without importing them. Constructions and revision history are managed alongside them by Barncept.

$ vendor/bin/barncept init
$ vendor/bin/barncept gui
InstallationInstall from Packagist

Require Barncept, its command line and its browser app:

$ composer require rmb32/barncept rmb32/barncept-cli rmb32/barncept-gui
